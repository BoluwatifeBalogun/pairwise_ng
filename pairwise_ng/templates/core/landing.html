How an allocation runs, start to finish

Nobody ranks anybody. Students write one honest sentence, supervisors declare what they do and how many students they can take, and the system does the comparing.

  1. Everyone submits once

    Students give matric number, CGPA and an interest statement. Supervisors give a specialisation and a capacity.

  2. SBERT reads every text

    Each statement and past project title becomes a 384-number embedding. A supervisor's profile is the average of theirs.

  3. Every pair gets a fit score

    Cosine similarity measures meaning, so “online store” still finds the supervisor of “e-commerce platforms”.

  4. Places go in CGPA order

    Highest CGPA first. Each student takes the best-fitting supervisor who still has a vacancy.

  5. A person signs off

    Weak matches and unplaced students are flagged. The coordinator resolves them, then publishes.

No supervisor goes over capacity

A place is given only while the vacancy counter is above zero, and the database refuses a capacity below one.

{% icon "user" 22 %}

One student, one supervisor

Matric number is the primary key of the allocation table, so a second supervisor cannot be recorded for the same student.

{% icon "list-ordered" 22 %}

Higher CGPA is served first

Ties go to the stronger best fit, then the lower matric number, so the same input always gives the same result.

{% icon "flag" 22 %}

Nothing is quietly accepted

A match below the coordinator's threshold, or a student with no place left, is flagged for manual review.

One system for departments across Nigeria

Nothing in the design is specific to one discipline or one school. Each department brings its own supervisors, past projects, matric format and CGPA scale, whether 4.00 or 5.00.
